Transformer internals

Parallel training, sequential decoding

A decoder trains on every position at once but generates one token at a time. Both compute the same function. One property of causal masking is why, and why the KV cache is exact rather than approximate.

Naman Jaswani·05 September 2026·~14 min transformersinferencekv-cache

Take a decoder-only transformer. Push a whole sequence through it in one forward pass and note the logits at position 20.

Now throw that away. Feed the model one token at a time, keeping each step's key and value vectors so you never recompute them. Read the logits at position 20 again.

You get the same numbers. Not close numbers, the same ones, down to the last bits of the mantissa.

The two procedures look nothing alike. One is a batch of large matrix multiplications. The other is a loop that grows a buffer. They agree because of a single property of the decoder: a token's representation never depends on anything to its right. Parallel training, the exactness of the KV cache, and the failure of both to transfer to an RNN are all consequences of that one fact.

Teacher forcing and the causal mask

A decoder-only language model is trained to predict the next token. Given a sequence of tokens x0, x1, ..., x(n-1), the objective sums a next-token prediction over every position:

L(theta) = - sum_t log p_theta( x_t | x_0 ... x_{t-1} )

Teacher forcing is the choice of what to condition on. At position t the model could be fed the tokens it predicted itself for positions 0 through t-1, or it could be fed the true tokens from the training data. Teacher forcing means feeding the true ones. The name comes from recurrent network training, where it was introduced as a way to keep a network's state from drifting during training by clamping it to the correct history.

This is what buys the parallelism. At every position, the correct target is already sitting in the training batch. Position 5 is trained to predict token 5, and it does not need the model's guess at token 4 first, because token 4 is right there in the data. Nothing waits on anything. All n predictions can be computed in the same forward pass.

There is one obstacle. Plain self-attention lets every position read every other position. If position 3 can read position 4, it can see the token it is being asked to predict. The model would score almost perfectly and learn nothing. So the scores get an additive mask before the softmax:

S = QK^T / sqrt(d_h) + M, Attn(Q,K,V) = softmax(S) V

Here S is the matrix of attention scores, one per query-key pair, and M is the mask that is added to it before the softmax. The mask has one entry per pair, and it takes one of two values:

M_ij = 0 if j <= i M_ij = -inf if j > i

An additive -inf sends that weight to exactly zero, so row i of the output is a weighted sum over positions 0 through i and nothing else. Stack that through every layer and the containment holds all the way to the logits.

The next claim carries the rest of the post. Write F for the model and y_i for row i of a masked forward pass over the whole sequence:

y_i = F(x_0, ..., x_i) for every i, independent of x_{i+1} ... x_{n-1}

Row i of the batched pass equals what you would get by running the model on the prefix alone and reading its last row. Not approximately, and not closely enough for practical purposes. Exactly, up to floating point summation order.

The reason is easy to check. Every operation in a decoder block does one of two things. Layer norm, the feed-forward block and the output projection each work on one position at a time, so they cannot move information sideways at all. Attention is the only operation that mixes positions, and the mask has already stopped it reading rightwards. That leaves no path through the computation graph from a later token to an earlier row. Change token 20 and rows 0 through 19 do not move.

Two ideas get run together here. Teacher forcing is about what you feed. Causal masking is about what each position may read. Parallel training needs both. An RNN can be teacher-forced and still has to be unrolled step by step, which is the last section. A transformer without the mask runs in parallel and learns nothing.

The cost of teacher forcing Training conditions on true prefixes; generation conditions on the model's own output, mistakes included. The two distributions differ, so errors made during generation can compound in ways training never rehearsed. This is called exposure bias, and it is a separate topic from this post.

Generation, and the loop that redoes everything

At generation time there is no true continuation to feed. Only the prompt exists, and every token after it has to be produced before anything can condition on it. The parallelism disappears, for no architectural reason: the inputs simply are not there yet. The loop is forced.

toks = list(prompt)
for _ in range(n_new):
    logits = model(toks)          # full forward pass over everything so far
    toks.append(argmax(logits[-1]))

That version calls the model on the whole sequence at every step. The usual explanation is that the attention interactions between tokens have to be recomputed each time. That explanation is wrong, and the real one is more useful.

The interactions do not change. Row i depends only on tokens 0 through i, so appending a token to the end leaves every earlier row bit-identical, at every layer. Nothing in the past is stale. The naive loop recomputes it anyway and gets back exactly what it had.

The real constraint is about state. The new token has to attend to every previous position, so every previous position's key and value vector has to be available. Available, not fresh. An RNN meets that by carrying one fixed-size vector h_{t-1} summarising everything before it. A transformer meets it by keeping the history uncompressed: one key and one value per position, per layer. The naive loop is what you get when you have nowhere to keep them.

The waste grows with the sequence. Step t pushes t positions through the network, so generating n tokens pushes about n^2/2 position-slots through it, each paying for a full set of projections and a feed-forward block. Generating 512 tokens from an 8-token prompt sends 134,912 position-slots through the model. Only 520 of them are positions it has not already seen.

The KV cache is bookkeeping

The fix is to keep the vectors. For each layer, hold two buffers that grow by one row per token. At each step, project only the newest position, append its key and value to the buffers, and attend against everything the buffers hold. Writing || for appending a row:

K_{0:t} = K_{0:t-1} || k_t, V_{0:t} = V_{0:t-1} || v_t, o_t = softmax( q_t K_{0:t}^T / sqrt(d_h) ) V_{0:t}

There is no mask in that expression, and none is needed: the buffer only ever holds positions that are already in the past. The mask and the cache enforce the same containment two different ways, one by zeroing forbidden weights and one by never having the forbidden vectors around at all.

Per step, the projections and the feed-forward block drop from t positions to one. Attention does not, since the new query still has to be scored against t stored keys. So the expensive dense terms become constant per step, leaving a residual that grows linearly with context length.

Three different quadratics "Attention is quadratic" is true of three different things, with three different exponents. Counting only the attention term, for a sequence of length n:
  • Training is O(n^2). Every one of the n queries is scored against every key, once.
  • Naive generation is O(n^3). It redoes that O(n^2) work at each of the n steps.
  • Cached generation is O(n^2). Step t scores one query against t keys, and those add up to n^2/2.
So the cache removes one factor of n, taking generation from cubic to quadratic. It does not make attention linear.

What makes this legal is the property from Section 1. A stored key can never be invalidated by a token appended after it, so reusing it carries no error term at all. It is the same number. That is unusual for a cache. Normally a cache is a bet that stale data is close enough; here staleness cannot happen.

The two loops are the same arithmetic, differing only in what gets stored and what gets thrown away. Run them side by side on the same weights and the only disagreement is in the last bits of the mantissa, from summing the same products in a different order.

The cache keeps vectors that the naive loop computes and then throws away.

What the cache costs

The cache trades arithmetic for memory, and the memory is not small. For a batch of b sequences at context length n, on a model with L layers, H_kv key/value heads, head dimension d_h, at s bytes per element:

cache bytes = 2 (K and V) * L * H_kv * d_h * n * b * s

Everything except n and b is fixed the moment the architecture is chosen, so the cache grows linearly in context length and in batch size, off a constant you cannot change later. For Llama 3.1 8B, 32 layers with 8 key/value heads of dimension 128, that constant is 128 KB per token in fp16. At its full 128k context, one sequence needs 16 GB of cache. The weights are about 15 GB.

Shrinking that constant is what multi-query and grouped-query attention are for. Shazeer argued in 2019 that incremental decoding is bound by the memory bandwidth of repeatedly reloading the key and value tensors, and proposed sharing one key/value head across all query heads. Grouped-query attention later settled on an intermediate number of key/value heads, with a recipe for converting existing multi-head checkpoints instead of retraining. The effect shows up in the configs. Llama 2 7B and Llama 3.1 8B have the same depth and the same head dimension, but the first keeps 32 key/value heads and the second keeps 8, so the cache per token drops from 512 KB to 128 KB.

Why this does not transfer to an RNN

An RNN is teacher-forced too, with the ground-truth tokens supplied as inputs. So why can it not compute all positions at once? The answer is in the shape of its update:

RNN: h_t = f(h_{t-1}, x_t) decoder: y_i = g(x_0, ..., x_i)

The RNN's hidden state at step t consumes the hidden state at step t-1, which is an output of the previous step. You cannot start step t until step t-1 has finished, however much hardware you own, because the thing you need does not exist yet. The decoder's row i consumes only inputs, and those are all in memory before the pass starts. Every row can go at once.

Measure that difference as the depth of the dependency graph: how many rounds of computation you would need with one worker per node and unlimited workers. Both answers fall out of the recurrences directly. A decoder node at layer l waits only on layer l-1, all of which finishes together, so the whole model completes in L+1 rounds. A recurrent node waits on layer l-1 and on its own left neighbour, which chains, so the model completes in n+L rounds. At four layers the decoder needs five rounds whether the sequence is 4 tokens or 128. The RNN needs 8 and 132.

Depth and speed are different things, though, and it is worth being clear about what shallow depth actually buys. It means the work can be spread out. It becomes speed only if you have hardware wide enough to spread it onto.

The decoder also does more arithmetic than the recurrence at the same width. Self-attention carries an n^2 d term from scoring every pair of positions; the recurrence carries only n d^2. Past roughly n = d the attention term dominates and keeps growing. On a single core, where nothing can be spread out, an RNN finishes first.

So it is a trade. The decoder spends extra arithmetic to buy a dependency graph shallow enough to fill a GPU, and on a GPU that is an overwhelmingly good deal. It is why the architecture won. On one core it is a bad deal.

One part of the recurrence penalty survives any hardware. Even with free arithmetic, the RNN pays a fixed cost per step simply to sequence the steps, n times, in an order nothing can rearrange. Latency like that does not shrink when you buy a wider machine.

There is a neat symmetry in where this ended up. The transformer gave up the RNN's compact recurrent state to get parallel training, then spent memory at inference time buying a state back. The KV cache is that state, uncompressed and growing without bound. Much of the recent work on state space models and linear attention is an attempt to get the parallel-trainable structure and the fixed-size state together.

The takeaway

One sentence to keep: in a causally masked decoder, a position's representation is a function of that position and everything before it, and of nothing else.

Everything else here follows. Teacher forcing plus that property means the batched training pass and a sequential unrolling compute the same thing, so you may as well run the fast one. The same property means a stored key can never go stale, which is why the KV cache is exact rather than a heuristic. An RNN lacks the property, because its state consumes the previous state instead of the previous input, and that is why none of this transfers to it.

What decided things on real hardware was never raw speed. It was the shape of the dependency graph, which determines whether the work can be spread out at all.
